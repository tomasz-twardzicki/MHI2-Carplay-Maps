# P4521 step-3 failure and 20-minute vehicle report

Reported 2026-10-29 for `MU1367-P4521-v1.4.0-experimental` (791 cluster).
The tester stopped at step 3; the infotainment remained usable. Steps 1/2
were exercised, but settings, lane guidance and later optional layers were
not installed successfully. This report is not vehicle acceptance of v1.4.0.
The tester confirmed **direct USB**, and that omonob's v2.0.1 package and
the navigation-ignore patch had both been fully uninstalled beforehand.
This is not an adapter test or evidence of an active competing installation.

## Confirmed installation blocker

The screenshot reads `MU1367_SETTINGS_FAIL=UNEXPECTED_BASE_menu`.
The original step-3 controller requires `eso/hmi/lsd/jars/VCMenu.jar` to be
absent. The failure establishes that a regular file exists there. The
provided export does not include its hash or bytes, so its origin cannot be
proven from this export. The stock P4521 firmware has no file at that path.
Prior upstream settings installation is a plausible source of a dormant JAR.

This check fails before creating the settings recovery directory or replacing
targets. The exported boot line contains our three native/audio JARs and
the step-1 controls JAR, but no `VCMenu.jar` prepend. The core is 75,099 bytes,
the bridge 67,835 bytes and supervisor 56,849 bytes: the older step-1 runtime
remained active. The expected newer step-3 transport was never installed.

The v1.4.1 migration accepts only these **dormant** upstream MU1367/791 JARs:

## Reported runtime symptoms and available evidence

| Observation | Evidence and limits |
| --- | --- |
| Map stutter, pixelation, occasional “starting map” | Old bridge logs contain 13,584 PTS rebases, 179 slow writes, maximum MOST write duration 982 ms and queue high-water 1,224. Two early stream-timeout fallbacks are recorded. These support transport disruption, but do not establish one root cause or prove every reported restart is explained. Re-evaluate after successful step 3. |
| Arrival/time/distance bars work | Tester observation. Native reader accepted 14,177 polls and adapter recorded 23,393 writes with no reported write failures. These are internal counters, not display acknowledgements. |
| Native arrows/totals intermittently disappear | Final reader state is `ended`, reason 3: **WORKER_FAILED**, not route cancellation. The 32-byte mailbox independently contains END(5)/WORKER_FAILED(3). The native reader terminated and has no automatic restart; the HMI correctly clears output on END and can still report `error=0`. This explains a persistent blackout after that failure, though not every earlier transient disappearance. |
| Oil-temperature view jumps back to maps | Old runtime has `CLUSTER_AUTO_ENABLE`. This is a possible contributor, not proof of the specific view change. The export lacks time-aligned HMI focus/view commands. Retest after step 3 with a deliberate view switch. |
| Media text without cover | Expected for this v1.4.0 bundle; it contains no artwork layer. `covers=0` alone is not an artwork-install failure. Do not apply K4525-only artwork/recovery packages to P4521. |

The two screen connection errors near the end of `sloginfo.txt` cannot be
identified as main-screen versus cluster-screen failures from that line alone.
Avoid attributing native arrow loss to those errors without correlated data.

The native reader's `WORKER_FAILED` covers its 1,500 ms worker deadline,
worker pipe EOF/select errors and monotonic clock failures. The final mailbox
overwrites the preceding invalidation detail; this export cannot identify
which path fired. 14,177 valid polls and 3,233 invalid polls preceded exit.
The HMI's 24 releases and zero reported failures do not show why every prior
release happened. Step 3 installs a different video bridge/supervisor but
does not change this native reader, so it is **not a reader recovery fix**.
The failed reader cannot be restarted by rerunning its current `start-live`
command against the existing RAM directory: that command intentionally
requires a new directory. Retain diagnostics and fully reboot for a new
reader session; do not delete a live reader's RAM directory.

Upstream [v2.0.1 release notes](https://github.com/omonob/MHI2-Carplay-Maps/releases/tag/toolbox-plaintext-v2.0.1)
describe a 790 map-centering change and explicitly retain both 791 native
cores. They do not substantiate a new 791 stutter fix specific to v2.0.1.
Our step 3 already carries the newer upstream bridge/supervisor from v2.0.0;
the failed installation left those components unapplied on this unit.
