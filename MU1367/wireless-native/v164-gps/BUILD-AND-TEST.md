# Building and reviewing v1.6.4-e-test1

The build is isolated from sealed v163-next and all previous ZIPs. `assemble.py` requires exact stable v1.6.1 plus v1.6.2-e-test1/v1.6.3-e-test2/test3 archive pins. `build-components.py` compiles the new source/tap/tuning/launcher and patches the guidance JAR against pinned factory classes. Unchanged media/BT/bridge components retain test3 hashes.

The local final component directory is `../build-gps-components-r3`; final clean stage is `../build-v164t1-stage-r2`. The QNX toolchain and Java tools are external host build inputs. Strong native imports are checked against fresh firmware libraries from both K4525/P4521 images and both HW50/HW70 variants; SDK-only imports are not accepted.

`tests/gps-host.py` exercises the parser/codec under sanitizers and factory dispatcher patching. `tests/gps-qnx.py` runs ARM source capture/publishing and OEM J9 verification/negative controls. `tests/location-receiver.py` exercises the actual receiver parser, serial queue and frame encoder. `tests/receiver-tap.py` checks default-off timing/guidance/media/RHD/audio behavior. `tests/unit-tools.py` checks native options, hash gates, pre-exec contracts and wrapper fallback. The SD-side GPS preference helper verifies the installed layer and remounts /mnt/app before writes; its failure/status paths use an explicit mount stand-in with actual native preference writes. Its input-preload comparison remains a known failure in both published control and candidate, explicitly not a functional pass.

Installer verification uses `tests/transactions.py` for all 45 targets and six failure/interruption sites, `tests/release-host.py` for real controllers across four layouts and prior versions, and `tests/release-qnx.py` for the production orchestration/collector in factory ksh. The final clean assembly was compared byte-for-byte with the tested first stage for every managed copy payload, wireless/release controller, compatibility table and combined collector. Host migrations require the saved v1.5.4 integration checkout (`../build-v161-stable-repo/MU1367/integration`) and `../build-v161-stable-host-inputs`; the current older integration fixture lacks the factory zlib/GAL seed and is not an equivalent baseline. Host hashing is a rebuild of the same C verifier. Native config-only output is replayed from its pinned QNX capture. Mount/reboot boundaries are explicit fixture substitutions.

`record-verification.py` binds component checks and retained unchanged-component evidence. `seal.py` independently requires final migration, factory-flow and transaction reports, verifies the exact staged component bytes and six GEM actions, rejects packaged opt-in flags, syntax-checks shell scripts and verifies every ZIP entry on readback. Verification reports are included under `Custom/carplay_mu1367_wireless_native/source/v164t1/verification-reports` in the ZIP.

The native source Unicode/lifetime boundary and receiver wakeup/remote transport boundaries remain controlled in tests. No bench result establishes passive NMEA availability on wireless, phone receipt, iOS sensor selection or vehicle navigation accuracy. Follow START_HERE.md for those acceptance checks.
