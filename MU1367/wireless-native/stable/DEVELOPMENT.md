# v1.6.1 stable packaging

The stable package promotes the exact test2 native runtime. Keep its component
hashes, build IDs and saved wireless controller unchanged when rebuilding this
release. The maintained v1.5.4 integration remains its base. New installer code
is isolated in `control.sh`; `diagnostics.py` extends the standard export.

`package.py` can rebuild the stage from the public stable ZIP without needing
the three earlier local experimental ZIPs:

```sh
python3 MU1367/wireless-native/stable/package.py \
  --seed-zip /path/to/CarPlay_Maps_VC_MU1367_791_v1.6.1.zip \
  --integration MU1367/integration \
  --output /path/to/new-staging-directory
```

The seed manifest supplies the checked historical controller identities and
target maps. Runtime payloads are verified against the promoted manifest.
The historical-input mode also accepts `--test1-zip`, `--v161-zip` and
`--test2-zip`, with exact archive pins.

`test-host.py` executes the real release, base, wireless, legacy and Android Auto
controllers in isolated trees. SHA verification is the same C implementation
rebuilt for the host; mounts/sync are mocked. The native-only config helper is
represented by replaying its exact QNX-generated bytes, verified against the
native helper's recorded SHA receipts. These are fixture substitutions, not
claims of native execution on the host.

`test-flow-qnx.py` executes the actual new release control and combined diagnostic
scripts with factory ksh/utilities. Its child transactions are explicit small
stand-ins; the real child flows are covered by host tests and the unchanged
wireless transaction already has 39 rollback/39 interrupted-recovery checks
under factory QNX. Prepared-state receipt/target validation, archive naming,
reboot boundaries and the real collector execute in the factory shell.

`seal.py` requires passing reports for all seven host tests/four layouts and the
factory-shell proof, checks exact runtime identity, preserves wireless-only
removal/recovery dispatch, checks shell syntax and verifies every ZIP entry on
readback. The ZIP includes current source and verification data. The native
implementation and its build/firmware proofs remain under `../v161`.
